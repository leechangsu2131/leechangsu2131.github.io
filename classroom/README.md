# 실시간 수업 모니터링 및 학생 관리

정적 홈페이지에서 교사가 수업방을 열고, 학생들의 화면 상태(3초 간격)와 접속 상태를 실시간으로 확인하며 원격 제어(안내, 주의집중, 페이지 이동, 내보내기)를 할 수 있는 기능입니다.

---

## 🏫 수업 코드: `HC302` 고정

- 수업 코드는 **항상 `HC302`로 통일**되어 있습니다. 교사도, 학생도 코드를 따로 입력할 필요가 없습니다.
- 학생은 [`classroom/student.html`](student.html)에서 **번호와 이름만 입력**하면 바로 입장합니다.
- 여러 선생님이 쓰는 다중 교사 인증 / 난수 방 코드 생성 로직은 `schema.sql`과 `teacher.html` 주석(`##`)으로 보존되어 있으며, 필요 시 복원할 수 있습니다.

## 🧪 1. DB 설정 없이 바로 실험하기 (모의실험 / Mock 모드)

Supabase 설정 없이도 브라우저 창 2개(교사 창 + 학생 창)로 **화면 캡처와 원격 제어를 즉시 테스트**할 수 있습니다.

1. [`classroom/teacher.html`](teacher.html)을 브라우저에서 엽니다.
2. **[🧪 모의실험 모드로 시작]** 버튼을 누릅니다.
3. **[👉 학생 창 열기 (테스트)]** 버튼을 눌러 새 창에서 학생 입장 화면을 띄웁니다.
4. 학생 창에서 번호(예: `3`)와 이름(예: `홍길동`)만 입력하고 **[수업 참여하기]**를 누릅니다.
5. 학생 창이 `education.html`로 이동하고, 좌측 하단에 `🧪 [모의실험] 수업 화면 공유 중` 표시가 뜹니다.
6. 교사 창에서 **3초마다 학생 화면이 갱신**되는 것을 확인하고, 주의집중·안내·페이지 이동 등 제어 기능을 테스트합니다.

## 🚀 2. 실제 교실 수업에 적용하기 (Supabase 연동, 1회 설정)

1. [Supabase 대시보드](https://supabase.com/dashboard) → **SQL Editor** 에서 `classroom/schema.sql` 전체 내용을 붙여넣고 **Run**합니다.
2. **교사 계정 만들기** (수업 화면 관리는 교사 계정으로만 접속됩니다)
   1. Supabase 대시보드 → **Authentication → Users → Add user**에서 교사 이메일과 비밀번호로 계정을 만듭니다 (Auto Confirm User 체크).
   2. **SQL Editor**에서 허용 이메일을 등록합니다. 이메일은 공개 저장소에 올리지 않도록 여기서만 입력하세요.

```sql
insert into public.classroom_teachers(email) values ('교사이메일@example.com');
```

   3. 등록되지 않은 계정은 로그인해도 학생 화면 조회·제어가 모두 거부됩니다. 비밀번호를 잊었으면 SQL Editor에서 `update auth.users set encrypted_password = crypt('새비밀번호', gen_salt('bf')) where email = '교사이메일';`로 바꿀 수 있습니다.

3. 이후 [`classroom/teacher.html`](teacher.html)에서 교사 계정으로 로그인한 뒤 **[🚀 수업방 열기 (HC302)]** 버튼으로 수업을 시작합니다.
4. 학생들은 [`classroom/student.html`](student.html)에서 **번호와 이름만 넣으면** 자동으로 HC302 수업방에 입장합니다.

## 🔒 3. 화면 캡처 및 개인정보 보호 원칙

- **캡처 범위:** 학생이 현재 보고 있는 **우리 홈페이지 탭 화면**만 브라우저 내에서 렌더링(html2canvas)하여 전송합니다.
- **제외 대상:** OS 전체 화면, 다른 프로그램, 다른 인터넷 탭, 웹캠/카메라, 마이크는 기술적으로 절대 접근하지 않습니다.
- **학생 고지:** 화면 하단에 항상 "수업 화면 공유 중" 표시가 고정되며, 학생이 언제든 공유를 일시 중지하거나 나갈 수 있습니다.
- **데이터 최소 보관:** 화면 캡처는 DB에 가장 최근 1장만 보관(덮어씌움)되며, 수업 종료 시 즉시 파기됩니다.

## 📝 4. 단원평가 배포 관리 (교사 로그인 후 화면 맨 위)

교사 화면 위쪽의 **단원평가 배포 관리**에서 시험마다 세 단계 중 하나를 고릅니다. 학생 화면(`tests/`)이 이 단계를 읽어 시험지·오답노트·점수를 열거나 잠급니다.

| 단계 | 시험지 | 오답노트·점수 | 쓰는 때 |
|---|---|---|---|
| 🔒 미배포 | 잠김 | 잠김 | 시험을 치기 전 (현재 수학 4단원 분수) |
| 📝 시험 배포 · 오답노트 미배포 | 열림 | 잠김 | 시험 보는 중, 채점 전 |
| ✅ 완전 배포 | 열림 | 열림 | 채점·검토를 마친 뒤 |

- 단계는 DB의 `unit_test_release`(`exam_open`, `released`)에 저장되고, 바꾸는 일은 교사 계정만 할 수 있습니다(`unit_test_release_set`).
- 단원평가 목록(`tests/index.html`)에서는 열리지 않은 시험·오답노트 카드가 아예 보이지 않습니다. 주소를 직접 열어도 잠금 화면이 나옵니다.
- 오답노트·점수의 개인별 조회는 DB가 따로 막고, 시험지·오답노트 화면은 `tests/release-gate.js`가 가립니다.
- 상태를 확인하지 못하면 대부분의 시험은 열리고, 시험 전인 단원(분수 시험지·오답노트·점수)은 잠긴 채로 남습니다(`data-default="hidden"`).
- **한계:** 학생 화면 잠금은 화면을 가리는 방식입니다. 문항 파일은 공개 저장소에 있으므로, 문항 자체의 유출까지 막으려면 시험 당일까지 해당 파일을 저장소에 올리지 않아야 합니다.
- 새 시험을 만들면 교사 화면 목록에 id가 나오도록 `teacher.html`의 `EXAMS`에 이름을 추가하고, 처음에는 🔒 미배포로 두세요. 설정 SQL은 `test/release_setup.sql`입니다.

## 📋 6. 수업 활동 (클래스툴처럼 활동 띄우기 · 수업 흐름 저장)

수업방을 열면 교사 화면에 **"📋 수업 활동"** 칸이 생깁니다.

1. 한 번만: Supabase **SQL Editor** 에서 [`activity/schema.sql`](activity/schema.sql) 다음에 [`activity/schema_draw.sql`](activity/schema_draw.sql)(그림 활동) 을 실행합니다(이미 적용돼 있으면 건너뜁니다).
2. **단계 추가**: 📷 사진(얼굴·이름 나오지 않게 확인 체크 후 보냄, 학기 초 초상권 동의 범위 안에서) / 🎨 그림(학생이 그림판에 그려 냄 — 큰 화면 갤러리, 그림 ZIP 저장, 7일 뒤 자동 삭제) / ✍️ 주관식 / ✅ 객관식(① ② ③ 보기를 칸마다 따로 쓰고 정답은 보기 옆에서 체크) / ▶️ 영상 보기(유튜브 주소) / 🌐 페이지 열기(이 사이트 안의 주소)를 순서대로 쌓습니다.
3. 이름을 쓰고 **💾 저장**하면 다음 수업에 목록에서 **불러오기**로 같은 흐름을 쓸 수 있습니다.
4. **▶ 처음부터**, **다음 단계 ▶** 로 진행합니다. 학생 화면에는 큰 카드가 뜹니다.
5. 진행 중에는 제출 현황과 막대(객관식)가 보이고, **🖥 큰 화면으로 보기**로 모두의 답을 크게 띄웁니다(이름 가리기 가능). 객관식은 **정답·결과 공개**를 누르면 학생에게 정답이 나옵니다.
6. 단계마다 **복제**, **⏱ 시간 제한**(0이 되면 자동 마감, 이 화면을 열어 둘 때만), **📝 교사 메모**(학생에게 안 보임)를 쓸 수 있고, 흐름은 **파일로 내보내기/가져오기**(.json)로 옮길 수 있습니다.
7. 흐름은 **다른 이름으로 저장**해 복사본을 만들 수 있고, 오늘 수업 전체는 **ZIP**(전체결과.csv + 그림·사진 폴더)으로 한 번에 저장할 수 있습니다.
8. **CSV 저장**(이 활동 / 오늘 수업 전체)은 엑셀에서 바로 열립니다.

| 파일 | 역할 |
|---|---|
| `activity/schema.sql` | 표 3개와 `cra_` 함수 10개 |
| `activity/schema_draw.sql` | 그림 활동·시간 제한·7일 자동 삭제 추가분 |
| `activity/teacher-activity.js` | 교사 쪽 모듈 (`ClassroomActivity`) |
| `activity/student-activity.js` | 학생 쪽 모듈 (`ClassroomActivityStudent`, `monitor.js` 가 자동으로 불러옴) |

모듈을 빼려면 `teacher.html` 의 `activityPanel`·스크립트·`mountActivity` 와 `monitor.js` 의 로더 부분만 지우면 됩니다. 흐름 목록은 최근 사용순/이름순으로 정렬되고 마지막 사용일이 보입니다. 앞으로의 계획(그림·사진·동시 그리기·ZIP 저장 등)은 `AGENTS.MD` 의 "다음 이행 목표" 를 보세요.

## ⚙️ 5. 기술 구조 (유지보수 참고)

| 파일 | 역할 |
|---|---|
| `classroom/teacher.html` | 교사용 수업 관리 화면 (수업방 열기·학생 목록·제어) |
| `classroom/student.html` | 학생 입장 화면 (번호·이름 입력 → HC302 자동 연결) |
| `classroom/monitor.js` | 모든 학습 페이지에 삽입되어 화면 캡처·교사 명령 수신을 담당 |
| `classroom/schema.sql` | Supabase 테이블·RPC 함수 정의 (1회 실행으로 설정 완료) |

- **통신 방식:** Supabase RPC(Security Definer) 함수만 외부에 노출, 테이블 직접 접근 차단
- **모의실험 통신:** `BroadcastChannel` + `localStorage` 듀얼 버스 (file:// 환경 대응)
- **캡처 순위:** ① WebRTC 탭 직접 공유(고화질) → ② html2canvas DOM 렌더링 → ③ SVG 메타데이터 프리뷰(폴백)
- **상대경로 로더:** `file://` / 웹서버 환경 무관하게 `monitor.js`를 항상 정확하게 로드하는 스마트 로더 사용
